# 共有資料の変更を判断して復元する

2026-10-05。監視の改善に続く限定サイクル。対象はNextcloudの世代比較。全ソフトの改善完了を示す記録ではない。

## 実プレイで選んだ問題

通常資金の会社でDAY2を再開し、日締めを2回行った。DAY4に新たに現れた、つばさ文具の「共有リンクの有効期限を設定」を標準価格¥6,008で手動受注。社員として注文CSVを読み込み、PO-1001の金額を12,800から12,900へ変更・提出した。これはQA用の架空資料で、実際のPUTによってファイルと過去版が保存された。

旧比較は「保存内容」と「現在内容」の別々の表で、両方の金額列が画面外に隠れていた。「差分一覧」という見出しだけでは、どの注文の何が変わったのか見つけられない。新しい説明カードを増やすのではなく、実データの比較表を作り直した。

今回の達成条件は、実際に提出した金額の旧値・新値を同時に見られること、色以外でも変更を識別できること、復元失敗後の再試行と再開後の未送信内容を保持すること、960×600・文字130%でも納品・入金まで主要操作を行えることとした。

手動受注後・実変更後のQAセーブを監査フォルダーの `accepted-with-actual-edit.json` に保持。SHA-256は `09894ed82f2cab9354e1aaec5615a867fdaaf782e231b00d92ee007b636876fa`。旧画面の元画像は `03-before-diff-hidden-total.png`。

## 実装した判断の道具

- 一つの表で注文・顧客・金額を揃える。変更セルは枠・背景に加えて「−旧値／＋新値」、行はΔ・＋・−・↕でも区別する。
- 最初は差分だけを表示。「全行を表示」で通常業務の周辺レコードも開ける。「次の差分」で表の内外をスクロールし、変更箇所へ移れる。値が長い時は省略表示とツールチップ、元の内容は折りたたみの詳細で確認する。
- 既知のID見出しが先頭列にあり、双方で一意・空欄なしの場合だけIDを照合する。それ以外は「行位置で比較」と明示。行の追加・削除による位置ずれを、大量の内容変更や移動として数えない。
- 一意の見出しで列を照合し、同名列・空の見出しは位置へ戻す。見出しより長いデータ行、空欄と欠けたセル、列の追加・削除・位置変更も保持する。
- CSVの形式差だけの場合はその旨を表示。壊れたCSVや大きすぎる入力は、比較できないことを表示して元の内容へ案内する。
- 表は先頭32列・200表示行までに制限し、超過を明示。件数は比較全体に基づく。モデルは2MB・10,000行・256列・500,000セルまで。追加・削除・移動は行数、変更は対応する行の内容変更数。移動は共通IDの順序から必要最小限を算出する。

純粋な文字列比較を追加した。表示・全行切替・差分移動でファイル、過去版、測定、作業時間、資金を変更しない。ファイル更新と復元は既存の明示操作を使う。セーブの構成は変更せず、任意の表示設定 `portal_ui.diff_all_rows` だけを既存セッションへ保存する。

## 確認した流れ

手動受注とは別に、実際に完了したDAY2の通常資金セーブのコピーから、公開APIによる日締め・自然に出た案件の受注を準備した。接続後はGodotのマウスとキー入力で、社員のCSV変更・提出→比較→保存失敗を起こした復元→保存先を戻して再試行→受取側の再読込→未送信の編集内容をセーブ・再開→閲覧専用取引先の更新拒否→リンクの7日設定→9項目の実診断→納品→請求確定・入金を操作した。

復元は保存した元のバイト列を戻し、置き換えた12,900の内容も次の世代として残す。受取側のGETが12,800へ戻ったことを確認。更新拒否・保存失敗では元ファイルと履歴を保ち、再試行用の入力を失わない。中断時の保存・再読込はAPIで行い、未送信の12,910と保存済み12,800が混ざらないことを確認した。

最終ログ・PNG・操作記録はローカル `artifacts/github-publication/audit/sharing-business-20261005/`。表示中の文字列と実セルを比較し、金額セルの全体が表示領域に入ること、件数ラベルが一行で読めること、ボタンの高さが文字拡大に応じた範囲に収まることを確認した。初回の画面確認で見つかった縦伸びは修正済み。画像はゲームの元出力で加工していない。

最後に改善前の手動セーブも1280×720で「続きから」開き、保存されていた案件・実ファイル・選択中の過去版から、新しい表に12,800／12,900が同時に表示されることを確認した。元画像は `04-after-manual-aligned-change.png`。この手動セーブ自体は未納品のまま残し、完了検証用のコピーとは分けている。

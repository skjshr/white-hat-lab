# 請求サービスの対応演習

請求ポータルの「運用」から、保存した案件のコピーを使う対応演習を開始できます。通常の請求画面、認証、請求書更新、CSV生成を使って事件と業務を進めます。外部のサービスには接続しません。

## 開始と進行

Godotで `game/project.godot` を起動し、自由キャリアの営業一覧から「ミハマ請求ポータル・公開前診断」を受注します。作業PCで「セキュリティ運用コンソール」を開き、「運用」へ移動してください。納品済みの案件でも演習を開始できます。

シナリオを選び、必要なら条件番号を入力して開始します。同じ番号は同じ初期条件、空欄や別の番号は異なる条件になります。標準シナリオと通信中心のシナリオで、調べる操作と必要な復旧が変わります。

最初に顧客の運用予定を読み、操作記録と照合してください。同じ利用者の複数の接続があり、利用者名だけでは対処先を決められません。記録のセッション、端末、対象の請求書と、顧客が依頼した作業の範囲を比較します。判断に使った記録を保存できます。

対処や業務の更新、「1分進める」で演習の時間が進みます。記録を読む、画面を切り替える、入力途中で考える操作では進みません。通常の会社経営の時間も、演習を表示している間は停止します。

## 判断と復旧

セッションの失効は、その接続だけを無効にします。CSVの一時停止は出力の被害を抑えますが、正規の利用者も出力できなくなります。「業務を確認」は実際の請求操作と出力を試し、失敗も記録します。正規の接続を失効させた場合は、新しいログインで回復を確認します。

「請求書の版」では変更内容を比較し、復元する項目を選べます。古い内容を丸ごと戻すと、その後に行われた正規の変更も失います。復元は履歴を削除せず、新しい版を作ります。別の更新と競合した場合は、最新の版を読み直して判断してください。

「対応を評価」で現在の状態を確認し、必要な対処を続けられます。結果を確定すると、流出、未復旧の変更、正規業務への影響、根拠となる記録、復旧確認を振り返り、再挑戦できます。すでに取得されたデータは、元の請求書を直しても取り戻せません。

終了後は結果を固定し、記録や版の閲覧ができます。請求業務を続ける場合は「通常業務へ」、新しい対応を試す場合は「結果と再挑戦へ」を選択してください。

## 中断と保存

「通常業務へ」で演習を保存して元の案件に戻り、後から「運用」→「演習を再開」で続けられます。終了済みの場合は「運用」→「結果を見る」で振り返ります。元の案件の請求書、証拠、提出状況、下書きは演習と別に保持します。演習の成功は元の診断案件の検証や納品を代行しません。

## 検証用の入口

`game/tests/test_incident_response.gd` は業務モデルと事件進行、`test_incident_integration.gd` は保存・会社経営との分離、`test_incident_ui.gd` は実画面の操作を検証します。通常のプレイヤーセーブを使わず、`--qa-profile` を指定して実行してください。UI試験はGodot内の入力イベントと一部のコントロール操作を使い、人による使い勝手の評価とは区別します。

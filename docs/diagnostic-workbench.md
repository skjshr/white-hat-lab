# HTTP診断の観測作業台

支店案件を新規受注して注文APIの検査を実行したところ、現行画面はタイムアウト文と長い照合値を並べていた。今回はHTTP診断を、端末・通過/遮断位置・応答サーバー・取得した注文票・原本照合の作業台へ改修する。

達成条件は、通信遮断、200応答と原本不一致、共有元が読めても形式異常になる422応答、復元後の合格を異なる状態として確認できること。各造形から実際の証拠を開き、保存した観測だけを再生する。画面操作による再検査・修復・課金は、検査実行や明示したサービス操作に限る。

## 情報の出所

`diagnostic_observation.gd` は、既存の公開検査項目と保存した応答だけを読む。HTTP応答、JSONに実在するレコード、実在する共有元、実測SHA-256を使う。未測定の結果や、届かなかった先のデータは表示しない。受入合否は既存VMの検査結果に従い、200だけで合格にしない。原本照合は省略した図柄ではなく64桁全体を比較する。

点滅や常時流れる架空の通信は使わない。1回の保存記録を約1.4秒で再生し、検査を実行した表示とは分ける。古い観測は変更前の印と破線を残す。HTTP200で金額が変更されていれば、注文票は取得できた状態、原本の照合は不一致になる。

構成上の参考は、[Wiresharkの選択した通信から詳細を開く構成](https://www.wireshark.org/docs/wsug_html_chunked/ChUseMainWindowSection.html)と、[Postmanの応答を図として調べる仕組み](https://learning.postman.com/docs/use/send-requests/response-data/visualizer/)。UIはゲーム内の観測と業務データに合わせて描画し、外部サービスに接続しない。

## 検証範囲

検証記録は `../audit/diagnostic-evidence-20261005/` に保存した。1280×720の通常GUIの手動プレイでは、実際に利用可能になったDAY5案件のQAコピーで見積・受注・顧客接続・検査失敗まで操作し、通常終了後に同じセーブから再開した。

修正版の通常GUIでも再開し、ゲート選択で証拠全体が表示されることを確認した。証拠からpfSenseへ移動してLANの宛先443だけを許可にし、保存・適用・再検査。経路は到達、応答は503、資料は共有元から取得不可になった。通信の復旧だけで案件を合格にせず、注文票から `files01.client.test /srv/share/partner-order.csv` の実応答を調べて通常終了した。画像は `13-manual-inspector-visible.png`～`15-manual-source-evidence.png`、保存は `manual-after-https-repair.json`。

通し検証では、同じ利用可能な案件の受注を公開キャリアAPIで準備する。その後は描画されたGodotの部品にマウス・キー入力を送り、ファイアウォールと共有の修復、注文金額変更、形式異常、履歴からの復元、古い観測の再検査、中断再開、納品、評価、請求回収まで操作した。保存先への書き込み失敗も注入し、再試行と状態保持を確認した。解答・資金・VM状態の直接注入は行わない。原本のプレイヤーセーブは使わずQAコピーに限定する。

記録は `wide-inspector/` と `narrow-inspector/`。全5造形の証拠をマウスとキーボードで開き、内容全体が追加スクロールなしで見えることを検査する。手動で発見した「展開した詳細が画面下に隠れる」問題は、レイアウトとフォーカス移動後に表示位置を調整して修正した。検査実行は作業台の下へ移し、小さい画面でも図と同時に見えるようにした。

両方で評価A、請求 `INV/0005` の11880円が入金済み。所持金30014→41194、信用250→361、顧客満足70→75、会社レベル6→7。200応答でも金額12900への変更は原本保全が不合格となり、復元後の12800で合格する。図形選択・記録再生・応答比較では実行中のVM・作業時間・資金が変わらないことを確認した。初回・最新の実応答を開いて比較できる。

関連確認は、応答投影24件、既存診断モデル61案件、診断UI、応答比較の通常・狭幅、旧セーブの読み込み・保存し直し33件、エディター取込。原本のプレイヤーセーブと利用可能な案件の元ファイルはSHA-256が開始前と同一。

入力検証は既知の部品の実配置を調べてGodotへ入力する。Windowsのマウスで315操作したという意味ではない。入力の座標と押下をまとめて送るよう検証側を調整し、ポインター到達・押下1回の確認は残した。背景時計は通し検証で停止し、明示した作業による時間消費は保持する。通常GUIでの再開には実時間の経過がある。

開発者による実機操作と、既知の操作部品へのGodot入力検証であり、初見プレイヤーの理解や楽しさの検証ではない。外部画面取得での起動時黒画像は再現しており、[既存の切り分け記録](startup-observation.md)の限界を維持する。人の実画面でも起きるかは未確定。

次の最優先は、全体監視の3台を文章のカードではなく、実際の端末・共有資料・依存線と操作対象として描き直すこと。HTTP以外の診断、設備投資から次の判断へつながる表現も改善が必要。全ソフトの造形を統一せず、それぞれの仕事に適した操作構造を使う。

# ソフト間を往復する操作の安定化

## プレイで見つけた問題

最新ブランチ `7302be0` の通常GUIで、日報案件の保存拒否後のQAセーブを再開した。コピーを編集して保存すると、通知の表示中にタスクバーのアイコン群が左へ動き、通知が消えると戻った。前サイクルには、ファイルへ戻るつもりのクリックがメールを開いてしまった。今回も通常GUIの3枚の画像で前後の移動を再現した。

今回の達成条件は、保存・失敗通知とセーブ再開を挟んでも主要ソフトの位置が変わらず、前に見た同じ座標で同じソフトを開けること。仕事のファイルと失敗した入力を保ったままソフト間を往復し、受注から結果・入金まで確認する。

改修前の実入力テストでも、実際のエディター保存によってメールの矩形が `x=341` から `x=298` へ43px動いた。失敗は `../audit/taskbar-layout-20261006/native-before.log` に残る。

## 変更した配置と状態

ソフトの列を左を基点に配置し、空き領域と通知を右側へ置く。通知の幅や起動中ソフトの数で列全体を中央へ寄せ直す計算を取り除いた。主要7ソフトの名称と個別のアイコン、起動中の線、現在のソフトの枠と太い線は維持する。通知と起動数で位置を変えず、利用者が意図して横スクロールする操作は残す。

小画面で多数のソフトを開いたときは、キーボードフォーカスに合わせて該当するタスクボタンを表示する。スクロールした末尾のソフトからファイルへ戻る操作も確認する。仕事時間や測定・権限設定を、ソフトの切り替えだけで変更しない。

全ソフトを起動する確認で、通常案件から「専門作業」を開くと、存在しない高度案件データを参照するエラーが出た。作業モデルがないときは「高度案件の作業対象なし」と案件を開く操作を表示する。実際の受注でモデルが作られると、同じウィンドウをその案件の作業画面へ組み直す。案件データを表示の都合で作成しない。

## 検証方法

実際に前サイクルで納品・入金したDAY6の会社から、通常市場の日報案件を受注した。Godotのマウス・キー入力で日報取得と編集を行い、保存前の主要ソフトの矩形とウィンドウ内のピクセル座標を記録する。実際の保存通知、実時間での通知の消滅、転送保存失敗の持続、作業セーブの再開後にその矩形を比較する。元の座標で実際にクリックし、対象のボタンが1回押され、目的のソフトが開いたことを確認する。

この経路には、予算超過による受注拒否、見積下書きの再開、受注保存の失敗・再試行、コピーの未保存送信拒否、共有の保存拒否、来客を通す誤対応による納品拒否、誤対応後の保存再開、修正、転送保存のロールバックと再試行、読み戻し、納品・入金・結果の保存再開を含む。背景の作業時計は停止するが、明示的な作業時間と経費は加算する。資金・技能・出現案件・正解設定・測定結果を注入していない。

反復する確認で仕事時間は116分になり、90分の期限を超過する。基本料¥3,053、経費¥700、純利益¥2,353、入金後の現金¥58,317、つばさ文具の満足度75→60を保持する。UIの待ち時間を理由に、期限や結果を成功扱いへ書き換えていない。

多数のソフトの起動、長い通知、案件一覧へ戻るボタン、横スクロールとキーボード復帰は別のUI用フィクスチャでも確認する。こちらの初期会社は公開APIで準備し、通知はレイアウトの条件として設定する。実際の通知や経営成果の証拠は通しプレイと区別する。

検証中、旧専門作業テストが実際のクリック成立を確認せず、要求のない配列へアクセスしても不合格数0で終了する問題を見つけた。実際のホバー対象と1回のボタン押下を検査し、押す・離すの間にWindowsのマウス位置取得が割り込まないようにした。描画設定を通常のGraphics経由で適用し、ウィンドウのピクセル座標と論理領域を換算した。最終の判定では終了コードに加え、スクリプトエラーと途中の不合格も検査する。

カーソル位置の既存テストにも同じ入力の問題があり、通常の描画設定、座標換算、実際のホバー対象の確認を適用した。広い側の設定も、製品が受け付ける1600×900に変更した。実際のウィンドウは1600×900、論理領域1280×720となり、その倍率でクリックとカーソル保持を確認した。

## 残る課題

通常GUIの開発者操作と自動入力で実装を検証した。初見の第三者プレイヤーは未検証であり、理解のしやすさや楽しさを確認できたとは扱わない。起動直後の外部取得画像が暗くなる現象についても、[内部描画と外部取得の記録](startup-observation.md)の限界を維持する。

次は実際のアップロード画面をプレイして、編集コピーから共有先への転送と、拒否された位置を図で表現する。現在はパス入力と文字の結果が中心で、紙とコピーの作業面との連続性が弱い。

# 通常起動の表示確認

2026-10-05、共有案件の一周を検証する際、通常起動のウィンドウが黒／灰色のままになる現象を観測した。最大化で回復した起動と、操作せず表示された起動があった。リソースの読み込みは終了しており、別の観測起動では描画フレームも進んでいた。原因となるドライバー処理は特定できていない。

今回の達成条件は、手動のサイズ変更を要求せずタイトルから保存案件へ入れること、設定とウィンドウ寸法を起動処理が変更しないこと、小さい画面でも主要操作へ到達すること。

`Office._refresh_window_surface()` は描画完了を2回待ってから明示的に描画するよう変更した。起動直後にウィンドウを1ピクセル広げて戻す処理を取り除いた。セーブ、案件、設定形式は変更していない。

| 確認 | 結果 |
| --- | --- |
| 変更前の通常起動 | このサイクルでも灰色のままの画面を1回観測。読み込み後にスクリプトエラーなし |
| 変更後の通常起動 | 1280×720で3回。新規QA設定、同じ設定からの再起動、以前の案件途中のQA保存からの起動で、最大化せずタイトルを確認 |
| 設定の保持 | 同じQA設定の再起動前後で設定ファイルのSHA-256が一致 |
| 保存案件の再開 | 続きから→業務端末→納品前確認を実マウス／キーで操作。検証状態・工数・所持金を確認し、保存終了。セーブ読み込みにエラーなし |
| タイトル描画 | 既存 `test_title_scene.gd` をネイティブ1920×1080と960×600／文字130%で実行。両方 `TITLE_SCENE_OK`。描画画像を確認し、主要操作の欠けなし |
| 保存失敗と終了 | `test_save_exit_safety.gd`: 保存失敗で終了を取り消し、下書きを保持。成功した再試行で実終了。PASS |

テストとログは通常保存から分けたQAプロファイルを使用し、チェックアウト外の `../audit/startup-20261005/` に記録した。タイトルテストは寸法をAPIで設定するため、通常起動3回の確認とは分けて扱う。観測用の一時コードは取り除いた。

確認環境はWindows、Godot 4.7.2 Compatibility、AMD Radeon RX 9070 XT、OpenGL表示ドライバー26.8.1.260810。間欠的な現象の再発がないこと、別GPU・低性能PCでの動作、初見プレイヤーの理解は未確認。配布物の再作成・公開はしていない。

# 起動と下部操作の表示確認

2026-10-05、共有案件を一周する際、通常起動のウィンドウが灰色のままになる現象と、960×600／文字130%で通知後に下部の戻る操作が欠ける現象を観測した。

達成条件は、手動のサイズ変更なしでタイトルから保存案件へ入れること、設定・ウィンドウ寸法を起動処理が変更しないこと、通知・保存失敗・再開後も主要操作へ到達できること。

## 変更

起動時のプロジェクト設定を、Graphics が実行時に使う `canvas_items`／`expand` と揃えた。ウィンドウを1ピクセル広げて戻す処理と、その後の強制描画処理を取り除いた。先の `0341797` で導入した強制描画だけでは、通常起動4回目に灰色表示が再発した。この文書の最終確認は、その候補と区別する。

タスクバーは、表示中の通知・戻る操作・対象選択の実際の最小幅からアプリ列の幅を計算する。通知で一時的に広がったコンテナの横幅を残さず、通知の表示・消去時に配置を更新する。操作の見切れを各プレイ段階で検出する回帰確認を追加した。

## 後続比較：描画方式と起動方法

中止・再挑戦を実装した `8ef2e92` でも通常起動を再確認した。元のOpenGLで灰色のウィンドウを観測した際、起動後4秒の一時計測では121描画フレーム、245描画呼び出し、1280×720、タイトル表示中だった。Godot内部のビューポート画像にはタイトルと3Dオフィスが描かれていた。最小化・復帰で取得画面も回復した。`observer-1.log` に計測を記録した。一時計測コードは製品から取り除いている。内部PNGは後の比較で上書きされたため、最初の画像はツールでの目視確認である。

描画方式の比較候補としてWindowsだけ `opengl3_angle` を試した。[Godot公式設定資料](https://docs.godotengine.org/en/stable/classes/class_projectsettings.html#class-projectsettings-property-rendering-gl-compatibility-driver-windows) はWindowsのDirect3D 11経由のANGLEと、非対応時のnative OpenGLへのフォールバックを定義している。この設定を入れた通常起動10回ではタイトルが見えたが、追加の11回目で黒い画面を観測した。候補は取り消し、製品の描画方式は元のまま。エンジン内部の描画、Windowsの表示、画面取得のどこで差が生じるかは未確定である。

確認環境はWindows、Godot 4.7.2 Compatibility、AMD Radeon RX 9070 XT。起動は未解決で、次の最優先課題は直接起動・製品EXE・画面取得経路を分けた再発条件の特定。黒／灰色の取得画像だけから、実ディスプレイでも同じ表示だったとは断定できない。別GPU・低性能PC、初見プレイヤーの理解・楽しさは未確認。ローカル検証用EXE以外の配布物更新・公開はしていない。

通常案件の中止・損失・翌日の再挑戦は [career-closeout.md](career-closeout.md) の範囲で実装・検証した。納品後の実プレイでは、現金3,600円と未発行請求4,307円が別に存在し、確定後に現金7,907円となり、ゲートウェイ1台の調達相談に進めた。起動と独立して進められる次の体験課題は、この請求・手持ち資金・機材の準備を対象と状態変化で見渡せること。現在は金額と備品の文章を別画面で比較する必要がある。

# 会社の循環の検証記録（2026-10-04）

通常の初期資金5,000円から、4営業日・4契約を完了する旅程を実描画で確認した。会社の状態や正解を注入せず、既存の受注、修理、診断、納品、請求、日送りを使用した。

## 実際に通した旅程

1. つばさ文具の共有フォルダーを修理して納品。既存18段階の案内と修正前後の記録を使用。
2. 同顧客の共有リンク期限の指名相談を確認。実際に得たスキルポイントを使い、見積から受注。
3. 期限設定を変更し、正常利用の200と期限経過後の410を測定。未納品のまま翌日に持ち越し、実際に遅延納品。満足度75→60、次の相談は保留。
4. 通常市場の同顧客Samba案件を受注し、実修理・期限内納品で相談を再開。次のEDR案件のLv5・事故対応2という条件は維持される。
5. 請求書を発行して代金を回収。実際に得た現金から監視端末3,200円を注文し、実時間30秒の配送を待って設置。
6. 別顧客・青葉デザインのバックアップを作成し、退避データを選択して別フォルダーへ復元。内容の照合と検証を経て納品・請求回収。
7. Day4、現金12,010円、Lv4、4契約完了。2顧客・3サービス系統・設置済み業務設備・運転資金により第2目標を達成。
8. セーブ→タイトル→再開で、顧客、VM、設備、請求、現金、スキル、相談と獲得済み目標の一致を確認。オフィスに2つの達成トークンと監視端末が残る。

1440×900・100%と960×600・文字130%の両方で成功した。各207クリック・130キー操作、ホイールは28回／97回。Godotの入力イベントを用いた自動操作であり、操作箇所はソースから把握している。設備の受取・配置だけは既存の公開操作API3つを使い、注文・時間・機材状態は注入していない。最後の掲示板画像だけは撮影用にカメラを向けた。

## 回帰と境界条件

- 全128テストスクリプトを対象に、124本をheadless、描画必須の3本をnative、複数日旅程1本をnative両サイズで検証。
- 初回headless一括実行は123/124成功。会社画面のクリック遷移1件が単発で失敗した。同一コードで再現せず、根本原因は未確定。テストの表示位置安定待ち、別フレームの押下・解放、実際の押下通知1回の確認を補強し、元の遷移条件を保って最終headless128項目、native129／131項目に成功。元の失敗記録は保持した。
- 保存検証の最終修正より前に走った19本は、修正後に全件再実行して成功。残るテストは最終製品コードで実行した。
- 指名相談の単体187項目、実Game統合80項目に成功。保存失敗の巻き戻し、不正な相談データでの既存セーブ保全、再読込、市場枠と見積保護を含む。
- 目標集計25項目に成功。履歴整理後も既知の検証済み案件を数え、未知・falseの記録、配送箱、装飾品、未実施の点検収入は実績にしない。
- 現金1,000円・給与債務1,500円では、支払見込み1,000円・支払後未払い500円を表示。表示だけで残高や債務を変更しない。
- 保存に失敗した終了操作はゲームを閉じず、編集を保持する。旧動作を注入した負例では、子プロセスの終了コード0だけで成功と扱わないことも確認。

## 検証範囲の限界

Windows配布用EXEは別の保存領域で60フレーム起動し、描画・終了コード0を確認した。EXE自体で上記4日旅程を再実行した証拠ではなく、同じ製品ソースのnative旅程と分けて扱う。環境の証明書ストア・shader cache警告は記録し、構文・実行・リソースエラーとは区別した。

低満足30の別fixtureでは、通常案件で35まで回復しても、次の同顧客案件に必要なLv・スキルが足りず相談は保留された。他顧客の仕事は残るが、一定日数以内の完全回復は保証しない。

10〜20日の経営方針比較、保守と人員を含む第3目標の通常資金からの通し達成、初見プレイヤーの理解と楽しさ、最低動作環境は未検証。次の改善候補と実装した条件は[会社の循環の設計](company-ecosystem.md)に記載する。

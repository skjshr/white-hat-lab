# 今回のゲーム改善

各ループは、プレイで確認した問題、変える判断と行動、遊んだ結果を整理してから締める。テスト件数や表示項目の増加をゲームの改善の代わりにしない。検証は今回変えた判断・結果・保存を確かめる範囲に絞る。

## 2026-10-06: 保留した顧客との次の仕事

前回は納品後のメール・精算・顧客評価の食い違いを直した。ただし、その後の仕事へ進むところは改善が残った。

今回の通常プレイでは、日報の納品遅延で評価75→60、指名相談が保留になった。「この顧客の通常依頼を探す」を押すと、納品済みの仕事だけが表示された。実際に日締めした翌日も0件だった。次の仕事がない状態で同じ検索へ送るため、失敗の後を遊べない。

今回変える遊びは、保留した顧客への通常業務と、別の顧客からの仕事の優先順位を選ぶこと。関係を修復する候補を、既存の受注可能な通常案件から今日の営業枠へつなぐ。指名相談と通常業務は別に扱い、受注だけでは信頼も保留も回復しない。実際の期限内納品と顧客評価で相談が再開する。

確認する結果:

- 保留・技能・既存の見積・進行中の案件・市場の枠が、実際の受注候補に反映される。架空の報酬や合格結果を与えない。
- 顧客画面の対象と操作が、今日受けられる具体的な仕事を示す。他の仕事を選ぶ余地を保ち、未提示の仕事への空検索へ誘導しない。
- 実受注から対応・納品・精算まで進め、期限内の同顧客納品で保留が変わる。中断・保存再開と失敗時の結果も保持する。

実際に遊んだ結果:

- DAY7の顧客画面から、受注可能な「共有リンクの有効期限を設定」へ進めた。「今日の別の仕事」では別顧客の公開前診断8,775円なども比較できた。
- 顧客との関係を優先して基準6,008円から5,400円へ値引きし、下書き保存・通常終了・再起動後にも見積が残った。受注時点では評価60・相談保留のまま。顧客図に基準価格が残る食い違いを修正した。
- Nextcloudで取引先の閲覧権限を保ち、有効期限を7日にした。未保存では8日前のリンクへHTTP200でアクセスでき、保存後に同じ検査を再実行するとHTTP410になった。既存の認証・業務・監査条件も実画面で確認して納品した。
- 作業46/135分、期限内評価A。顧客満足60→68（品質+5・値引き+3）、報酬5,400円・品質ボーナス540円・経費700円・利益5,240円。INV/0009を確定して5,940円入金、現金63,557円。相談の保留が解除された。次の相談には対応スキル2が必要なので画面は「準備待ち」。通常再起動後も評価・入金・相談の状態が残った。

検証は会社循環・市場・変更した導線と見積表示・旧セーブ読込に限定した。通常GUIは960×600・文字130%で受注から納品・入金・再起動まで操作し、1280×720で修正後の図と見積の5,400円表示が一致することを確認した。1440×900と960×600・文字130%の導線・配置はGodot入力による自動検証も通過した。通常GUIのプレイは開発者の検証であり、初見プレイヤーの理解・楽しさは未検証。証拠はローカル `../audit/customer-followup-20261006/` の通常プレイ画像・下書き・納品済みセーブ・検証ログに保存した。プレイヤーの原本セーブとDAY6の元データのハッシュは変わっていない。

次の最優先課題: 技術作業が9項目の逐次検査へ偏り、今回の意思決定は仕事の優先順位と値付けに集中した。次は、通常業務を続ける対象と危険な共有を見比べ、業務影響から検証順を決める体験を優先する。検査を増やして難しくしない。

## 2026-10-06: 共有先と古いリンクの判断

最新b8fb220を、前回に実受注可能だったDAY7の見積下書きのQAコピーで再プレイした。実見積から受注・顧客接続・Nextcloudの資料を開くと、社員・取引先は文字の行に分かれ、現在の業務と古い共有リンクを同じ場所で比較できなかった。検査画面は個別項目の一覧で、業務への影響から選ぶ構成になっていない。

今回は資料と利用者を結ぶ共有図・期限の時間軸から、設定対象と実測の優先順位を選べるようにする。取引先の全部遮断と古いリンクの失効は、現在の業務に異なる結果をもたらす。設定中のプレビュー・適用中の設定・保存された観測を混同しない。

確認する結果:

- 実資料・適用中の共有権限・期限を図で見比べ、対象から編集する。色に加えて矢印・遮断記号・日数・操作名で状態を区別する。
- 「取引先の業務」「古いリンク」「公開・認証」などの観点を選び、既存の架空端末への実測を実行する。検査項目の数や正解を増やさず、保存・納品を既存の判定につなぐ。
- 全遮断による業務失敗、再設定と再検査、中断・保存再開、受注から納品・入金を通常GUIで操作する。旧セーブと小画面・文字拡大も確認する。

実際に遊んだ結果:

- DAY7の実見積5,400円から受注して顧客へ接続した。共有図に実資料 `partner-order.csv`（77 B）と社員・取引先・公開先の経路が現れ、対象を押すとその共有設定だけを編集できた。先に社員と取引先の業務を測定し、双方の閲覧HTTP200と取引先の更新HTTP403を確認した。その後、8日前・31日前のリンクもHTTP200になる問題を測定した。
- 取引先を全部遮断する操作を選ぶと、経路が破線と遮断記号へ変わり、再測定した取引先の閲覧はHTTP403・業務不一致になった。設定変更後の以前の測定は「変更前」と表示される。通常終了・再起動後にも遮断設定と失敗した測定が残った。
- 取引先の閲覧を戻して期限を7日にした。社員と現在の取引先はHTTP200、公開先はHTTP403、8日前・31日前のリンクはHTTP410。設定の時間軸と、別途実行した測定結果を同じ画面で比較できた。認証・監査も測定して納品した。
- 作業61/135分で期限内評価A。顧客満足60→68、会社の信頼533→585、会社Lv8→9、利益5,240円。INV/0009を確定して5,940円入金、現金63,557円。再起動後も入金と顧客評価が残り、保留していた相談は必要スキル不足による「準備待ち」へ変わった。失敗の操作・再設定・通信も納品時の監査記録に残った。

通常GUIで960×600・文字130%の受注・失敗・中断・再設定・再測定を操作し、1280×720で保存再開後の共有図から納品・入金・再起動後の会社画面まで確認した。小画面では共有図の検索サイド欄を外し、近接する7日・8日および30日・31日の表示位置を分けた。図の下の測定・編集操作へはスクロールで到達できた。色だけに頼らず、矢印・破線・遮断記号・日数・HTTP数値・変更前表示を併用している。

関連検証は既存のNextcloud画面テスト（標準表示・960×600文字130%）と旧プレイヤーセーブの再開に限定して通過した。描画だけではVM・時間・資金を変えないこと、対象だけの実測、測定の保存失敗と再試行も確認した。GUIで見つかった遅延読込スクリプトの型エラーを修正した。原本セーブとDAY7下書きのハッシュは変わっていない。証拠はローカル `../audit/sharing-decisions-20261006/` の通常プレイ画像・失敗中/納品前/入金後セーブ・検証ログに保存した。開発者によるプレイ確認であり、初見プレイヤーの理解・楽しさは未検証。

共有の閲覧・編集・有効期限・アクセス関係の設計では、[Nextcloudの共有マニュアル](https://docs.nextcloud.com/server/stable/user_manual/en/files/sharing.html)を参照した。ファイル、通信、設定、納品判定は既存のゲーム内架空環境を使用する。

次の最優先課題: 共有対象を比較して検証順を選べるようになった一方、業務への影響はまだHTTP数値に寄っている。次は既存の受取側画面を、社員の日報保存と取引先の資料確認という仕事の結果を比較できる形へ統合する。通信一覧や検査項目を増やすのでなく、同じ設定の変更が別の利用者の仕事へどう響くかを遊べる単位で改善する。

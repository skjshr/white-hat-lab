# 今回のゲーム改善

各ループは、プレイで確認した問題、変える判断と行動、遊んだ結果を整理してから締める。テスト件数や表示項目の増加をゲームの改善の代わりにしない。検証は今回変えた判断・結果・保存を確かめる範囲に絞る。

## 2026-10-06: 保留した顧客との次の仕事

前回は納品後のメール・精算・顧客評価の食い違いを直した。ただし、その後の仕事へ進むところは改善が残った。

今回の通常プレイでは、日報の納品遅延で評価75→60、指名相談が保留になった。「この顧客の通常依頼を探す」を押すと、納品済みの仕事だけが表示された。実際に日締めした翌日も0件だった。次の仕事がない状態で同じ検索へ送るため、失敗の後を遊べない。

今回変える遊びは、保留した顧客への通常業務と、別の顧客からの仕事の優先順位を選ぶこと。関係を修復する候補を、既存の受注可能な通常案件から今日の営業枠へつなぐ。指名相談と通常業務は別に扱い、受注だけでは信頼も保留も回復しない。実際の期限内納品と顧客評価で相談が再開する。

確認する結果:

- 保留・技能・既存の見積・進行中の案件・市場の枠が、実際の受注候補に反映される。架空の報酬や合格結果を与えない。
- 顧客画面の対象と操作が、今日受けられる具体的な仕事を示す。他の仕事を選ぶ余地を保ち、未提示の仕事への空検索へ誘導しない。
- 実受注から対応・納品・精算まで進め、期限内の同顧客納品で保留が変わる。中断・保存再開と失敗時の結果も保持する。

実際に遊んだ結果:

- DAY7の顧客画面から、受注可能な「共有リンクの有効期限を設定」へ進めた。「今日の別の仕事」では別顧客の公開前診断8,775円なども比較できた。
- 顧客との関係を優先して基準6,008円から5,400円へ値引きし、下書き保存・通常終了・再起動後にも見積が残った。受注時点では評価60・相談保留のまま。顧客図に基準価格が残る食い違いを修正した。
- Nextcloudで取引先の閲覧権限を保ち、有効期限を7日にした。未保存では8日前のリンクへHTTP200でアクセスでき、保存後に同じ検査を再実行するとHTTP410になった。既存の認証・業務・監査条件も実画面で確認して納品した。
- 作業46/135分、期限内評価A。顧客満足60→68（品質+5・値引き+3）、報酬5,400円・品質ボーナス540円・経費700円・利益5,240円。INV/0009を確定して5,940円入金、現金63,557円。相談の保留が解除された。次の相談には対応スキル2が必要なので画面は「準備待ち」。通常再起動後も評価・入金・相談の状態が残った。

検証は会社循環・市場・変更した導線と見積表示・旧セーブ読込に限定した。通常GUIは960×600・文字130%で受注から納品・入金・再起動まで操作し、1280×720で修正後の図と見積の5,400円表示が一致することを確認した。1440×900と960×600・文字130%の導線・配置はGodot入力による自動検証も通過した。通常GUIのプレイは開発者の検証であり、初見プレイヤーの理解・楽しさは未検証。証拠はローカル `../audit/customer-followup-20261006/` の通常プレイ画像・下書き・納品済みセーブ・検証ログに保存した。プレイヤーの原本セーブとDAY6の元データのハッシュは変わっていない。

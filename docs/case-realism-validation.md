## 遊びとして変えたこと

- 通信案件は顧客の請求一覧を実際に開き、失敗した要求を調べ、既存設定を保存・適用し、同じ一覧の受注を検索して納品する流れにした。設定を保存しただけでは直らず、適用前の観測は古いと表示される。名前解決に失敗しているのにHTTP503と表示する誤りを修正した。
- 台帳案件は「最新を復元してコマンドが成功すれば終わり」にはならない。最新保存も壊れているため、内容を見て正常な旧版を選ぶ。正常な台帳を取り出しても原本や対象外を壊せば受入条件を満たさず、修正してやり直せる。
- Backrestのファイル一覧を選択後に畳み、選択パス・版ID・実内容の比較・復元先・保全結果を近くに置いた。新しいチュートリアルは増やしていない。960×600・文字130%では版選択欄へのスクロールが必要な場合があるが、比較中にも版IDを表示する。

## 失敗・未実施・配布物

開発中の型エラー、PopupMenuへの誤入力、表示外Tree行を押した試験の失敗、過大な二拠点fixture、過剰な同時viewport条件、修正前の複合案件回帰はログごと保全し、最終成功数に含めない。採用最終実行に未解決のscript/parse/assertエラーはない。Windows証明書ストア・隔離環境のshader cache警告、および保存復旧試験の意図した読込失敗は区別している。

Windows ZIPは `white-hat-lab-windows-realism-preview.zip`、84,120,387 bytes。SHA-256は `8096aaf965476b11ef76893764d929dae294fc1033f5f0446c5c145182bae09b`。実行時ソース142ファイルの一致、ZIP整合性、ライセンス同梱、テスト・ツール除外を確認した。最終パッケージ後に変えたのは除外対象のテスト3本だけで、製品ソースとEXE/ZIPのハッシュは一致している。

実EXEを隔離保存先で60フレーム起動して画面を確認した。上記2案件と4日間試験はソースをGodotで起動した実画面試験であり、パッケージEXEで全経路を再実行したものではない。人間の楽しさ・学習効果の評価、全案件の文章改稿、実ソフト全機能の再現も未実施。今回の範囲を妨げる未解決ブロッカーはない。

# 機材の準備から顧客受領・入金まで

## プレイで見つけた問題と達成条件

2026-10-05、通常営業の修復納品と請求確定で得た現金7,907円から、港町クリニックのゲートウェイ調達・設定・納入を受注した。端末の接続は `hardware_unavailable` のJSONで止まり、届いたシリアルは一覧に載るものの、設定台につなぐ操作が別の3D操作体系に分かれていた。現物の準備と、業務通信の設定・検証・出荷を一周で見渡せることを今回の対象とした。

- 入荷・保管、設定台、顧客先を、同じ実シリアルの位置と状態変化で表す。
- 発注で現金が減り、実際の入荷待ちがある。未入荷・型式違い・他案件の機材を接続できない。
- 機材を接続しても、設定と検証は未完了のまま。保存・適用・実測を区別する。
- 最新の業務・保護の検証が通るまで発送できない。発送と顧客受領、納品と請求確定を分ける。
- 保存失敗で位置・割当・設定を復元し、同じ現物で再試行できる。中断・保存後の再開で結果を保持する。
- 1920×1080と960×600／文字130%で主要操作、エラー、シリアル、状態を確認する。旧セーブを複製して読み込み・保存・再開を確認する。

## 実装

機材発注に「準備台」を追加。台帳にある実際の型式・シリアルを現物として選び、入荷・保管から設定台へ接続する。設定台は3Dオフィスの机と同じ保存状態を使う。SSHの機材未接続エラーから準備台へ移動でき、既存の製品カタログ、シリアル一覧、手持ち・棚置きの3D操作も使える。

操作は既存の受取・接続・発送処理を一つの保存取引にまとめた。別の機材を持っている状態、型式、案件・対象、設定台の占有、保存、検証の条件を引き継ぐ。保存に失敗すると、機材の位置・案件割当・担当作業・VMの下書きとインスタンスを元に戻す。接続操作で設定を修復したり、合格した測定を作ったりしない。

端末・機材管理ブラウザ・診断ラボは既存の実VMを使う。準備台は記録された検証の鮮度と件数を表示し、明示的な操作で各ソフトへ移動する。発送は最新の検証と実際の非機材チェックを確認する。実際の入荷30秒・発送12秒を状態と進捗で表示し、受領前の納品を防ぐ。顧客受領後の納品確認は、VM検証時点の古い到着失敗を表示せず、現在の保存された機材状態を読む。描画で検証や保存を実行しない。

プレイで、操作欄の幅不足による通知の縦折り返し、現物の所有者表示と机の重なり、再検証後に残る古い発送失敗の通知、出荷確認から3Dオフィスへ戻ってしまう経路を見つけて修正した。主要操作と再試行は作業面のスクロールから独立した下部に置く。

## 実プレイの結果

通常営業で得た現金7,907円から、受注・発注・入荷・接続・保存終了・再起動・設定・実測・発送・受領・納品・請求確定を、Windowsの実ウィンドウをマウス／キーで操作した。架空のオフライン環境だけを使い、資金・答え・完了状態を注入していない。

| 確認 | 実際の結果 |
| --- | --- |
| 仕入れ | WHG-000001を3,200円で購入。現金7,907→4,707円。入荷後に現物を設定台へ接続 |
| 保存再開 | 終了・再起動後も同じシリアルと机上の現物が残り、SSH接続できた |
| 失敗と比較 | 未検証で発送すると拒否。DNSと特定のLAN業務HTTPSルールを保存しただけでは、適用中の通信は遮断されたまま。適用すると古い実測を再検査する表示になり、同じ通信の再測定で許可を確認 |
| 業務と保護 | 名前解決 `NOERROR`、業務HTTPS `HTTP/1.1 200 OK`、外部管理 `FIREWALL_DENIED` を診断ラボで明示的に測定。最新の非機材7項目が合格 |

| 継続する成果 | 作業経費700円、仕入れ3,200円。請求15,377円の確定で入金し、現金19,384円。顧客満足度63→68、信用29→143、会社レベル2→5。納品・請求に同じシリアルが残る |

処理の自動確認は `test_stock_preparation_transactions.gd`。その資金・技能・市場は明記した合成フィクスチャであり、通常営業の到達性とは区別する。型式違い、未入荷、他の手持ち・他案件、同一契約の別拠点への付替え、設定台の占有、保存失敗と同じ現物での再試行、実VMの通信不良→修復→計測→検証、発送拒否、保存失敗時のVM下書きの復元、発送の経過時間、別Gameへの保存再開、実際の受領・納品を確認して失敗0。準備台の投影を呼んでも、状態・資金・時計・VM保存・未生成のVMが変わらない。

`test_stock_preparation_ui.gd` は最初の通常案件を実際の公開APIで修復・納品・入金し、営業資金と機材案件への到達を準備する。機材案件の受注以降はGodotのマウス／キー入力を使う。保存先の故障注入と保存読み込みはAPI操作で、入荷・発送は実際の配送時計で進める。既知の操作IDを使うため、初見プレイヤーの理解や楽しさを示す検証ではない。

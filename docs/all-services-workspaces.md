# サービス別の作業画面

顧客サービス8系統と専門業務9系統を、それぞれの仕事に合わせた画面から操作する。Desktopの12アプリと会社管理の7画面は、その入口と社内業務であり、別サービスとして数えない。既存の18段階オンボーディング、修正前後比較、請求サービス、独立した対応演習は維持する。

## 顧客サービス

| 系統 | 操作と確認対象 |
|---|---|
| Samba | 利用者・共有・ACLを設定し、同じ共有の一覧・読取・書込を試す |
| Backup | 保存世代の実内容と現在のファイルを比較し、選んだ内容を復元する |
| Network / Firewall | 経路と通信条件を設定し、実測された一致ルールと応答を確認する |
| Identity | アカウントの状態、新しいログイン、発行済みセッションの失効を区別する |
| EDR | 端末とプロセスを調べ、隔離・解除後の業務アクセスを試す |
| 外部ファイル共有 | 受信者の権限・期限を設定し、CSVの表を編集・提出して版履歴へ反映する |
| 顧客・受注・台帳 | 顧客と受注の登録・変更・削除、台帳の追記と残高を扱う |
| 請求ポータル | 実ログイン後に請求書を作成・修正・承認し、CSVを出力する。対応演習は独立した状態で動く |

業務画面は共有元と同じCSVを正本とする。別画面での変更は表示に反映される。閲覧・更新表示は作業時間を消費しない。書込には読込時の版を渡し、競合や保存失敗では確定データを巻き戻し、未保存の入力を残す。

## 専門業務

| 案件 | 判断の中心 | 主な画面 |
|---|---|---|
| Hunt | 原記録と顧客の作業予定の照合 | 時刻・接続・端末の選択、原文、照合ノート |
| Network pentest | 観測した共有資源からの到達性 | 共有探索、ファイル原文、アクセス試験 |
| Recovery | 復元データと起動条件の健全性 | 候補比較、作業領域の編集、依存先、再接続 |
| DDoS | 処理負荷と業務継続 | 経路別流量、上限スライダー、測定履歴 |
| API authorization | 業務契約と実応答の差 | 利用者・操作・対象ID、要求履歴、原文と再試験 |
| Supply chain | ビルドから配布までの来歴 | 入力、工程、署名・実内容、配置先 |
| Cloud consent | 同意と発行済み接続の違い | アプリ別権限、申請、資料取得の実応答 |
| Malware | 条件を変えた観測と端末への影響 | 実験条件、観測履歴、実体の隔離と原状復帰 |
| Detection | 収集・検出条件と再生結果 | ルール入力、イベント、誤検知・見逃し |

`os_advanced_operations.gd` が受注した案件に対応する画面へ接続する。高度9系統のうちHunt・pentest・Recoveryは固有の作業画面を持ち、残る6系統は共通のウィンドウ部品と専用の作業内容を組み合わせる。API認可試験は請求業務を題材とした検査ツールであり、通常の請求処理とは操作目的が異なる。

表示用の観測と入力途中の内容を区別する。条件変更後の古い計測は最新結果とみなさない。誤隔離や一括遮断は実際に業務を止め、復元・解除後の再試験を必要とする。モデルとUIの双方で保存・再開を扱う。

## 補助アプリと会社管理

ファイル管理・SMB・エディタは、選択、編集中の内容、転送失敗、保存失敗からの再試行を維持する。診断ラボは任意のゲーム内URLと利用主体を試す道具、サービス管理は稼働・再起動・適用状態の入口とする。

会社側は、新規見積、受注済案件と配員、人員、設備、資金と保守、終業確認、日次実績を分担する。勤務変更・採用・見積・発注などの失敗は操作欄へ表示する。

## 主な検証入口

既存Godotでプロジェクトの通常起動手順を使う。自動試験は `game/tests` にあり、独立したQA保存先を使う。

```text
Godot --headless --path game --script res://tests/test_specialist_models.gd -- --qa-profile=advanced-check
Godot --headless --path game --script res://tests/test_business_transactions.gd -- --qa-profile=business-check
Godot --path game --script res://tests/test_advanced_ui.gd -- --qa-profile=advanced-ui --capture --narrow
```

専用検証は `test_service_workflows.gd`、`test_identity_endpoint_sharing_workflows.gd`、`test_business_cross_service_ui.gd`、`test_file_workflow_quality.gd`、`test_company_workflows_ui.gd`、`test_investigation_models.gd`、`test_story_firewall_probes.gd` にも分かれている。

旧形式の互換テストに使う `legacy_service_fixture.gd` と `care_fixture.gd` は再構成したスキーマデータである。欠落している当時の配布セーブそのものを検証したことにはならない。実描画試験は入力イベントとUIシグナルを併用し、全案件の手動ユーザビリティ試験とは区別する。

# 会社の仕事が次の仕事につながる循環

最初の受注で顧客の業務を直し、納品実績から同じ顧客の別サービスへ進む。会社画面で必要なスキル・現金・設備を確認し、仕事と投資を選ぶ。既存の見積、請求、給与、保守、実機材配置をこの循環に接続する。

## 既存の仕組みと今回の接続

|領域|既存の実動作|今回の接続|
|---|---|---|
|依頼と技術作業|架空の共有・復元・認証・通信・調査サービスが状態と応答を持つ|顧客の期待と実測結果を診断直後に表示し、専門案件の案内を実在する作業画面へ接続|
|経済|納期・事故・見積価格で報酬と満足度が変化。請求下書きと現金入金を分離|会社の現金、翌日入金、日締め支出、保守収支、請求への導線を同じ概要へ集約|
|顧客|満足度が見積上限・保守継続へ影響。保守は納品した環境を保存して点検・修理する|新しい実納品を起点として、同じ顧客の別サービスの指名相談を保存|
|投資と成長|スキルは案件を解放。設備は配送・設置され、時間短縮・保守枠・人員枠へ影響|相談の不足スキルを明示し、設置済み設備や顧客支援の実績を成長目標へ接続|
|営業日|需要の変動、持越し案件、保守費用、給与、請求入金|初回の仕事から自由営業へ移る際にも日次台帳を締め、翌日9時から開始|
|ゲーム内の報酬|利益・レベル・機材・社員が蓄積|保存された会社の節目をオフィス壁面の立体トークンとして残す|

## 指名相談

新たな納品の契約ID・顧客・実際の品質・満足度・元の案件を記録する。同じ顧客がいる現役の案件定義から、完了していない別サービスを選ぶ。古いセーブの不明な納品品質を推測して相談を付与しない。

初仕事の例は、つばさ文具の共有フォルダーから外部共有リンクの期限設定への相談。スキルや会社レベルに届かなければ、相談を消さず準備条件を表示する。資格到達後は通常の営業枠の中で優先し、既に準備した見積や受注を置き換えない。

遅延・手戻りの納品は次の指名相談を保留する。同じ顧客の受注可能な通常業務を既存の営業枠に優先し、実際の仕事と見積を顧客画面へつなぐ。既存の見積・進行中の仕事・市場の枠・技能・当日中止した仕事の制限を守るため、必ず当日提示される保証はない。候補がなければ準備や次の営業日へ進める。受注だけでは回復せず、同顧客への期限内納品と満足度40以上で指名相談を再開する。別の顧客の仕事を選ぶ導線も残す。

これ自体は現金やスキル、修理済み状態を付与しない。報酬・値付け・顧客満足・支払いは従来の実取引を使い、相談の表示・クリックだけでは受注も検証も行わない。

## 成長の節目

- **開業の一歩**：検証済みの仕事を納品する。
- **頼られる技術会社**：2顧客、2サービス系統、設置済み業務設備、3,000円の運転資金を揃える。
- **続く会社へ**：3顧客、実環境を引き継いだ保守先2件、未実施ゼロで点検収入を得た3日、雇用中の社員、確定給与の未払いゼロ、6,000円の運転資金を揃える。

配送箱や装飾品を業務設備として数えない。同じSambaを別モードで納品してもサービス系統を二重計上しない。旧セーブの定額保守収入を「実施した点検」に置き換えない。獲得日は保存に成功したときだけ確定し、資金不足や履歴の整理で過去のトークンを失わない。現在の運営状況は達成記録と区別して表示する。

## 次の改善候補

1. **中長期の経済バランス**：複数の経営方針で10〜20日を遊び、保守・人員・設備投資の回収期間と資金不足からの復帰を比較する。単一の自動解法の利益を楽しさの根拠にしない。
2. **顧客の継続性**：既存の保守資産と別サービスの相談を通したプレイ結果から、顧客ごとの業務上の出来事と会話を増やす。結果に関係しないランダム通知は増やさない。
3. **初見の判断**：案内を知らない人が、見積・納期・必要設備・失敗結果から自分で次の行動を選べるかを観察する。操作可能なテストだけでは理解や面白さを証明しない。
4. **見せ方と手触り**：実際に設置した機材、担当者、顧客からの相談、会社の節目がオフィスへ戻ったときに読み取れるかを確認する。新しいサービスを一律のボタン群へ寄せない。

競合AIやランダム事件の新設を、この循環の完成条件には含めていない。時間・維持費・納期失敗・顧客関係・既存の保守障害という、すでに選択の結果を持つ仕組みを優先する。

# 共有元から業務の再開までを確かめる

2026-10-05。対象は「支店の業務再開」の共有サーバー・受注台帳・外部提出をつなぐ限定サイクル。全ソフトの改善完了を示す記録ではない。

## 実プレイで選んだ問題と達成条件

前サイクルで実際に入金まで終えた通常資金の会社をコピーし、公開の日締めでDAY5へ進めた。所持金¥30,014、信用250のまま、自然に出た「支店の業務再開」を標準見積¥10,800で手動受注した。通信ルールを修正すると販売画面は通信拒否からHTTP 503へ進んだが、旧画面の「共有サーバー接続失敗」には共有元・実ファイルがなかった。正常時は共有元の表示自体が消え、会計画面も受注ファイルを参照元として表示していた。

今回の達成条件は、実際の共有元・画面ごとのファイル・取得した業務件数がつながって見えること、共有停止・ファイル欠落・データ形式異常を区別できること、Nextcloudで変更した実ファイルの結果が台帳へ届くこと、保存失敗の再試行と中断後の再開を保つこと、960×600・文字130%でも案件の納品・入金まで進められることとした。

受注前の実キャリア `day5-available-branch.json` のSHA-256は `efdaa2dd8fdd8d873b3e881570df0b9b1ddbb5e62ace877cc281785afe823c95`。手動受注後・通信修正後のチェックポイント `accepted-gateway-repaired.json` は `0775bea89210a2e36c781ee25d5ce386a0f71db25e4013f6e6e34ac721234606`。元プレイヤーセーブとは別のQA保存先であり、資金・技能・正解設定の注入はしていない。元画像は `01-branch-accepted.png` と `03-after-gateway-source-hidden.png`。

## ソフト間の実際の接続

Odoo風の紫の業務画面に、共有サーバー → 実ファイル → 業務レコードの流れを置く。Nextcloudの青い資料画面、pfSenseの通信ルール、Sambaの共有設定とは操作目的・構成を分ける。表示は業務APIの応答から導き、共有を使わない案件に架空の共有元を付けない。サーバー・資料・業務の状態は個別の✓・×・!・?と短い名称で示す。接続停止とアクセス拒否も分ける。

受注は `/srv/share/partner-order.csv`、顧客は `/srv/share/customers.csv` を使う。会計が要求する `/srv/data/ledger.txt` はこの共有案件には供給されないため、欠落として表示する。受注ファイルを会計の正常な参照元に見せない。件数は取得できた実レコードから数え、未取得や失敗を0件の成功として表示しない。

共有に接続できても、社員が提出した注文金額が数字でなければ、業務APIは形式異常を返す。ファイルの存在と業務の利用可能性を分けて表示する。画面には「前回の取得」であることを示し、別ソフトの変更後も更新ボタンで明示的に再取得できる。表示自体が設定・ファイル・測定・作業時間・資金を変更することはない。セーブ形式は変更しない。

## 検証の範囲

手動操作で問題を確認した後、受注前の実DAY5コピーから公開APIで自然に出た案件を受注する準備を行う。作業はGodotの実マウス・キー入力で行い、通信修復→共有保存の失敗・再試行→Samba再開→台帳の再取得→Nextcloudで壊れた金額の提出→台帳の形式異常→実ファイルの世代復元→台帳回復→顧客と会計の別の参照元→セーブ後の再開→3台の実診断→顧客評価→請求確定・入金まで検証する。

初回の画像確認で、状態名が一文字ずつ縦に並び、更新ボタンが縦に伸びる配置不具合を発見した。状態名を一行に固定し、長いパスと内部エラーは「詳細」に移した。図の件数・対象・更新が同じ画面に収まり、詳細は実マウスで開け、Enterでも閉じられることを確認した。文字の実寸幅・一行表示・ボタン高さもネイティブの検査へ追加した。旧画像は `layout-vertical-before-fix.png`。

最初の全行程では、共有の保存テストがディレクトリーを変更したため、先に取った社員の閲覧測定が古くなり納品が止まった。正解を注入せず、保存後に閲覧・拒否を実測する順で再試行した。保存内容の表示と、納品に使える最新の実測は別の状態として扱っている。

最後に改善前の手動プレイ保存も1280×720で通常起動し、「続きから」→自席PCで、新しい共有元の図・HTTP 503の詳細が表示されることを確認した。`04-after-manual-resume-source-flow.png` と `05-after-manual-source-details.png` に元のウィンドウ画像を保存。この手動保存は未納品のまま保持し、完了検証のコピーと区別している。

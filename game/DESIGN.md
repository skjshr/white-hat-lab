# Visual and interaction contract

Keep the native desktop and distinct application surfaces. Outwatch uses messages, Cockpit uses managed resources, the file manager transfers actual files, and diagnostics exposes recorded measurements. Display identity, current target, drafts, saved/unapplied configuration, and stale evidence clearly.

For the shared-folder home, arrange employee and visitor devices around the actual folder. Reading and saving are separate document actions. Connections show the observed outcome; the contract requirement is a separate mark. Unknown, stale, denied, permitted, and execution error use different shapes and short labels. Do not infer measured access from configuration or equate all denied requests with safety.

Use existing fonts and software colors, generous action targets, responsive geometry, and keyboard focus. The four main share actions must remain reachable at 960x600 with both game and interface fonts at 130%. Commands, raw responses, and detailed configuration remain available on demand. Avoid adding narrative cards or persistent instructions to explain the diagram.

Native rendered evidence and input tests verify implementation and reachability. They do not establish a first-time player's understanding or enjoyment.

The branch monitor is an equipment plan: a business workstation, shared-source NAS with two selectable paper files, and an external document browser. Draw the actual source fork, never a gateway-to-portal dependency. File presence, local original-content comparison, process activity, unapplied configuration and recorded consumer acceptance are distinct states. Unknown hosts remain unknown. Selecting a device, paper or measured route changes only the monitor selection and preserves keyboard focus; explicit diagnosis/control navigation changes the actual target. Keep those primary actions outside the scrollable evidence area at 960x600 and 130% text.

HTTP diagnostics use a charcoal observation bench: workstation, measured route, rack response, retrieved paper specimen and paired original/observed seals. Select the objects to inspect their evidence. Replay only recorded observations; unknown downstream data remains unknown. HTTP success, readable source, valid business data, original preservation and delivery acceptance are separate states. Name-resolution failures and unreachable connections must not imply a firewall block. Historical specimens keep an explicit stale mark and dashed connections. Raw commands, full hashes and first/latest responses remain on demand.

SMB diagnostics use a lavender access trace with the requested user, share folder, actual file-name specimens and a separate saved acceptance stamp. Missing share, failed identity, operation refusal and success stop at different objects. LS proves names only; PUT/GET receipts do not prove contents or original equality. Local SHA diagnostics instead compare two paper fingerprints, without a fabricated network link. Use all 64 hash digits for equality; the picture is a compact specimen, not the judge. Old observations keep amber historical wording and dashed connections. Preserve raw unknown responses, do not guess downstream state or an ACL cause from a generic denial. Shape inspection, focus navigation and finite replay must not run the VM or advance work.

After an actual local SHA response, retain its evidence while that resolved file's bytes, presence and public inspection condition are unchanged. Unrelated configuration or another file must not make this local comparison historical. A changed target must expire the evidence without inventing a new measured result. Old unmarked saves retain their existing freshness rule until explicitly remeasured; never promote their stale PASS while drawing.

The customer ERP source view uses a rack, a folded CSV sheet and a business object: a receipt for sales, a contact for customers and a ledger for accounting. Its solid, broken and dashed routes describe only the last fetched response. Unknown or unread resources stay empty. File readability and usable business data are separate stops. Clicking an object opens that recorded evidence without a fetch; refresh remains explicit. Keep enlarged object targets and visible keyboard focus at 960x600/130%, and preserve the actual response behind details even when its metadata names a different resource.

Delivery outcomes use a cream paper statement with a grade seal, before/after satisfaction markers, signed credit/level changes and a sales-minus-cost profit strip. Show the saved consequences before the evidence, including losses and deadline penalties. A site's paper opens only its own saved responses; a legacy site without probes must never borrow another site's proof. Missing historical fields stay unknown. The acceptance count includes saved checks and must not be mislabeled as measured probes. Keep profit separate from the actual invoice's current payment status. Drawing, selecting or resuming this statement must not measure, transact or reward again.

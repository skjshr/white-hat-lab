# White Hat Lab

Offline security-company simulation in Godot. The player accepts fictional customer work, examines evidence, changes the simulated environment, retests, and owns the delivery outcome. Existing contracts, customer files, economic history, and saves are authoritative.

Show the working objects and the consequences of actions. Keep real configuration, saved configuration, measurements, and delivery acceptance distinct. Rendering must never perform repairs, measurements, or transactions. Software applications retain distinct layouts and operations. Details belong behind an explicit action.

Improve one playable acceptance-to-result loop at a time. For each cycle, record the observed play problem, the changed player decisions and actions, measurable acceptance conditions, actual played outcomes, and the next priority in `docs/gameplay-cycle.md`. Test counts and extra explanatory text do not establish a gameplay improvement. Keep verification focused on the changed experience, including failed actions, retry, interruption, save/resume, and legacy saves. Inspect native wide and 960x600/130% screens. Automated input and developer play do not establish first-time player understanding or enjoyment.

Use the existing working branch. Commit and push small verified changes. Main merges, public deployments, paid services, secrets, and access changes require separate authorization. All security activity stays inside the game.
